# bdg_plugin_adofai — ADOFAI 导出插件

将 Beat Data Generator 的踩点工程导出为 **A Dance of Fire and Ice (.adofai)** 关卡文件。

---

## 一、使用

### 安装 / 开发

- 发布：把本文件夹放入宿主编辑器的 `<userData>/plugins`。
- 开发：插件宿主在开发模式下会扫描项目根目录的 `plugins/`，把本目录作为扫描根即可。
- 改代码后做语法检查：`node --check renderer.js`。

### 使用流程

1. 在工程里新建插件轨道：**多押轨道**、**BPM 轨道**（旋转轨道已从 UI 移除，旧数据仍生效）。
2. 在这些轨道上踩点，并按需填写踩点属性（多押类型 / 角度、BPM 类型 / 数值等）。
3. 打开「**ADOFAI 导出设置**」面板，选择核心模型并按需调整选项（带 `?` 的项可查看说明）。
4. 用面板底部「**导出 .adofai**」、顶部「导出」菜单或「插件」菜单的导出按钮生成 `.adofai`；若命中导出检查会弹窗提醒（不阻拦）。

> 多押参数由多押轨道的踩点属性驱动；`songFilename / bpm / offset` 仍由工程快照提供。

### 轨道一览

**多押轨道** `dev.bdg.adofai-export:multi`（「多押轨道」/「多押点」），踩点表单三个字段：

- **多押类型**：`单轨`（single）/ `中旋`（midspin）/ `多押`（multi）
- **最大押数**：默认 `3`（范围 2–8）
- **多押角度**：`1° / 5° / 15° / 22.5° / 30°`（默认 `15°`）

**BPM 轨道** `dev.bdg.adofai-export:bpm`（「ADOFAI BPM 轨道」），字段：

- `speedType`：`multiplier`（倍频）/ `bpm`（BPM 值）
- `value`：数值

**旋转轨道** `dev.bdg.adofai-export:twirl`（「ADOFAI 旋转轨道」/「旋转点」），无字段。

## 二、两种核心模型

面板顶部用分段按钮切换 **核心模型**，或用「模型预设」一键套用该模型的默认组合：

| 预设 | 说明 |
|---|---|
| **旧版 0.2** | 轨道生成完全复刻 0.2（多押固定折返、`dir` 参与步进）；新版轨道启发式（吸附 / 快速跑动 / 发卡后处理）强制忽略；Twirl 用手动轨道 / 旧“双押旋转” |
| **新版 0.3** | 轨道按 0.3 生成（多押内圈折返、`stepSign` 跟随）；预设默认开启**自动 Twirl**（新版轨道需要它才正常） |

> 面板跟随宿主明暗主题；设置在改动后自动保存，底部提供「恢复默认」与「导出 .adofai」。

核心模型切换 3 处互相冲突的行为；此外旧版模型会强制忽略吸附 / 快速跑动 / 发卡后处理（它们属于新版轨道生成）：

1. **多押折返方向**：`legacy` 固定 `+(180−angle)`、`carry=+angle×blocks`；`modern` 按当前走向取内圈 `s`、`carry=s×angle×blocks`，并让后续走向跟随 `stepSign`。
2. **正常步进符号**：`legacy` 用 `dir`；`modern` 用 `stepSign`。这影响了手动 Twirl 的镜像结果。
3. **Twirl 来源**：`legacy` 用「手动轨道 + 旧版双押旋转」；`modern` 用「手动轨道 / 自动 Twirl」。

> 兼容保证：`legacy` 的轨道产物与 0.2 逐字节一致（即使配置里残留开启新启发式；`pauseFix2` / 装饰泳道属于独立功能）；`modern + 手动 Twirl` 与 0.3 默认一致，`modern` 预设默认 `自动 Twirl`。

### 配置迁移

设置以 `api.storage`（键 = `config`，按插件隔离、主进程落盘）持久化。

- 旧配置（无 `configVersion`）若没有 0.3 的新键 → 迁移为 `legacy`，并保留旧的“双押旋转”为 `legacyDoubleTwirl`。
- 旧配置若已包含 0.3 的新键 → 迁移为 `modern`，旧的 `doublePressTwirl=true` 映射为 `twirlMode="auto"`。
- 无法判断时默认 `legacy`，保证“升级不改谱”。迁移后立即回写，避免重复迁移。

## 三、导出设置面板（「ADOFAI 导出设置」）

### 导出模型

- **核心模型**：`旧版 0.2` / `新版 0.3`。
- **预设按钮**：一键切到对应模型的默认组合（旧版 = 手动 Twirl + 新启发式关闭；新版 = 自动 Twirl），不会改动你的容差/间距等个性化值。

### 变速 / 暂停

- **变速放置位置偏移**（默认 `1`）：生成的 `SetSpeed` 事件 `floor += 偏移`（正数往后挪格）；`floor ≤ 0` 仍按 floor 0 规则写进 `settings.bpm`。
- **暂停数值修复#1**（默认开）：对 `Pause` 的 `duration` 做修正 —— `(1,2)` 向上取整为 `2`，`(2,3)` 向下取整为 `2`；关闭则保持 `diffEff − 1`。
- **暂停数值修复#2**（默认关）：修复#1 之后 `duration > 2` 时再减 1 拍（部分回头/大间隔谱面实测会多停 1 拍）。

### Twirl

- **Twirl 来源**：
  - `手动轨道`：使用旋转轨道上的点（默认）。
  - `自动（按最终角度）`：不区分押数，按最终 `angleData` 逐块检查。维护“上一个显著转角（阈值默认 `|Δ| ≥ 90°`）的符号”，符号变化时在该块生成 `Twirl`；发卡弯（`> 179.5°`）不参与。开启后忽略手动 Twirl 轨道，避免重复翻转。新版预设默认选中它。
  - `关闭`：手动/自动都不生成。
- **旧版双押旋转**（默认关，仅旧版模型生效）：多押 `multi` 且押数 `= 2` 时，在该 beat 原格之后第 1 个插入格生成 `Twirl`，并从该格起翻转 `dir`。等价于 0.2 的 `doublePressTwirl`。

### 步进与角度

- **近整拍吸附**（默认关，仅新版模型）：踩点拍差距离整数 ≤ **容差**（默认 `0.05` 拍）时按整拍计算；角度、Pause、导出检查共用同一份吸附结果。旧版模型强制忽略。
- **快速跑动形态**（默认关，仅新版模型）：连续的细分拍（`diffEff < 1` 且该 beat 不是多押）按形态决定走向 —— 8 分三角、6 分三角、16/32 分之字、12/24 分同号；关闭时保持原有同向走向。旧版模型强制忽略。
- **发卡弯同号 / 闭环朝上**（默认关，仅新版模型）：实验性后处理，整体改写 `angleData` —— 让所有发卡弯强制同号，并把累计转角闭合且整体朝下的段落沿水平轴镜像朝上。旧版模型强制忽略。
- **多押折返方向**（仅新版模型）：`自动（内圈）/ 强制内圈 / 强制外圈`。默认自动与 0.3 一致。

### 装饰泳道

- **生成装饰泳道**（默认关）：按轨道颜色生成菱形/行星装饰、小节线（按首拍所在小节对齐）与红色播放头，并在关卡同目录写入 `bdg_lane_*.png`。关闭时不生成装饰也不写图片。
- **泳道间距**（默认 `0.5` 格）、**四分音符间隔**（默认 `0` = 自动）、**小节拍数**（默认 `4`）。

### 导出检查

- **导出前检查**（默认开）：命中变速区间/多押夹角时弹窗提醒（仅提醒，不阻拦导出）。关闭后不再生成提醒。

## 四、说明

### 多押轨道

**状态机语义**：多押点是「模式」标记——从该点起改写当前处理状态，并持续作用到后面，直到遇到下一个多押点再切换；初始状态为单轨。处理规则统一：每个 beat 都按当前状态生成。

**只处理真·多押音砖**：只有同一 beat 上有 **≥2 个音砖** 时才按状态处理；普通单押 beat 一律不处理（即使当前状态是多押）。各状态的处理结果：

- `单轨`：合并成单块（不插入）。
- `中旋`：在**原格之前**插 `[X₁, 999, X₂, 999, …]`，即 `[X₁, 999, …, 原格]` 写法（真·中旋，N 押 N 键）。押数 = `min(押数, 最大押数)`，插 `押数 − 1` 对 `[Xᵢ, 999]`；第 i 个折返角 `sᵢ = i × 多押角度`。`T − Σsᵢ < 15°`（装不下）则该点多押**跳过**并记日志。
- `多押`：在**原格之后**插 `min(押数, 最大押数) − 1` 块，每块 travel 均为多押角度（`180 − 多押角度` 的折返）。
  - `legacy`：固定正向折返，`carry` 累加为 `插入块数 × 多押角度`。
  - `modern`：折返方向 `s` 按原格走向取内圈，`carry = s × 插入块数 × 多押角度`，后续走向跟随 `s`。

**约束**：多押点必须落在某个音砖的 beat 上，否则导出会被拒绝并弹窗提示。

### BPM 轨道

**BPM 累积**：从 `baseBpm` 起按顺序套用每个点——

- **BPM 值**：绝对重置当前 BPM；
- **倍频**：乘在**当前 BPM**上（连续两个 `2` 倍频 ⇒ ×4；若前一个是 `120`，其后倍频以 `120` 为基数相乘）。

角度换算用累积后的倍率：`diffEff = 拍差 × (累积BPM / baseBpm)`。
事件字段：倍频 → `bpmMultiplier = value`（游戏按当前 BPM 累积），`beatsPerMinute` 写累积后的绝对值；BPM 值 → `beatsPerMinute = value`、`bpmMultiplier = 1`。

**约束**：BPM 点必须恰好落在某个音砖的 beat 上，否则导出会被拒绝并弹窗提示。

### 旋转轨道（Twirl）

> 已从 UI 移除（不再可创建），但内部生成逻辑（`readTwirlSet` / `buildTwirl` / `dir` 镜像）保留。若工程里仍留有旧旋转点，且 Twirl 来源为 `手动轨道`，导出仍会生效。

```json
{"floor": 76, "eventType": "Twirl"}
```

**约束**：旋转点也必须落在某个音砖的 beat 上，否则拒绝导出。

## 五、技术细节

### 文件结构

```
bdg_plugin_adofai/
├─ manifest.json   # 插件元信息（id=dev.bdg.adofai-export）
├─ renderer.js     # 渲染进程入口：导出逻辑 + 类型化轨道 + 面板
├─ main.js         # 主进程入口（预留，目前仅一个 ping 处理器）
└─ README.md
```

### 导出的 .adofai 结构

```json
{
  "angleData": [...],
  "settings": {...},
  "actions": [...],
  "decorations": []
}
```

### angleData

每块按 `step = (1 − diffEff) × 180`（mod 360）累计，`diffEff = 拍差 × 局部BPM倍率`。

### settings

默认值取自样例 `level.adofai`，仅 3 项由工程快照覆盖：

- `songFilename` ← `audioName`
- `bpm` ← `baseBpm`（若 BPM 轨道点在 floor ≤ 0，则改为该点累积后的 BPM，因为 floor 0 的 `SetSpeed` 会被引擎忽略）
- `offset` ← `offsetMs`

### actions

- `Pause`：当相邻音砖有效拍差 `diffEff > 2` 时插入（放在间隙末块，floor=`beatFloor[j+1]`），时长 `duration = diffEff − 1`。
- `SetSpeed`：来自 BPM 轨道，`{"floor","eventType":"SetSpeed","speedType","beatsPerMinute","bpmMultiplier","angleOffset":0}`；`floor` 会加上「变速放置位置偏移」。同 floor 时：新版模型排序为 `SetSpeed → Twirl → Pause → MoveDecorations`；旧版模型精确复刻 0.2 的排序（`Twirl → Pause → SetSpeed`，因 `order || 3` 把 0 当作假值）。
- `Twirl`：按「Twirl 来源」生成；手动轨道落在 `beatFloor + 1`。
- `MoveDecorations`：装饰泳道开启时，播放头从首块线性移动到末尾。

## 已知问题（未解决）

1. **Pause 时长规则不统一**：`duration = diffEff − 1` 在多数点位实测正确（如 floor2、floor4），但个别点位（如 floor64，`diffEff = 6`）用户反馈应为 `diffEff − 2`；两者无法用单一规律同时满足，待厘清。
